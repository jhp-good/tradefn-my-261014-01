# buyers 시트 진단 (2일차)

- 대상: `data/checkpoints/d2_start.xlsx` → `buyers` 시트. 150행 × 28열이고 머리글은 1행이다.
- 성격: **진단만 했다.** 원본은 고치지 않았고, 사본도 만들지 않았다.
- 코드: `scripts/d2_profile_buyers.py`. 실행은 `uv run python scripts/d2_profile_buyers.py`.
- 기준: 같은 파일의 `dictionary` 시트(열 정의)와 `dirty_list` 시트(정제 과제 목록).
- 행 번호: 엑셀 기준이다(머리글 = 1행, B001 = 2행).
- 판정 근거가 시트 안에 없으면 '확인 필요'라고 적었다.

- 셀 안에 적힌 통화 글자(CNY · EUR)는 3건 모두 `currency` 열과 같다.
- 숫자 변환은 진단용으로만 했다. 콤마 · 공백 · 통화 글자를 지우고 `k`는 ×1000으로 읽었다. 원본은 바꾸지 않았다.

## 4. 단위 의심: USD 환산 잔액 > 신용한도 × 10 (dirty_list 4번)

- 환산식: `잔액 × (krw_close ÷ 단위) ÷ USD krw_close`. 환율은 `fx_at_ref` 시트에서 기준일 `ref_date = 2026-08-31` 행만 썼다.
  - USD 1,368.25 · EUR 1,589.50 · CNY 203.62 · JPY100 856.55
  - (2026-10-15 정정) 처음에는 ccy별 최신 행(2026-09-30, 기준일 이후)을 써서 미래 정보가 섞였다. 그때 값은 배수 948.5, 한도 초과 38건이었다.
- 통화 표기 매핑(진단용): usd · US$ → USD, euro → EUR, yen → JPY, RMB → CNY.

| 행 | buyer_id | currency | ar_balance | ≈ USD | 한도 | 배수 |
|---|---|---|---|---|---|---|
| 73 | B072 | euro | 8320000 | 9,665,368 | 10,000 | 966.5 |

- 기준(×10)에 걸린 것은 1건이다. 연령구간 `ar_1_30` = `'8,320'`과 비교하면 1,000배 차이가 난다. 원천 확인이 필요하다.
- 참고로 잔액이 한도를 넘는 바이어(1배 초과)는 39건이다. 이것은 단위 문제가 아니라 한도 초과 여부의 문제라서 따로 판단해야 한다.
- 엔화 잔액(예: B028 `32072000`)은 큰 숫자지만, 엔화 단위로 환산하면 기준에 걸리지 않는다.

## 6. 정합 검사 (위반 0건)

- `country_code` → `region` · `oecd_crc` 1:1 대응
- `late_invoices_12m` ≤ `invoices_12m`, `dispute_cnt_12m` ≤ `invoices_12m`
- `max_dpd`가 속한 연령구간에 잔액이 있고, 그보다 오래된 구간에는 잔액이 없음
- `total_liabilities` ≥ `current_liabilities`, `accounts_receivable` ≤ `current_assets`
- TT_ADV(선수금) 12개사는 잔액 0 · max_dpd 0
